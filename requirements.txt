# The database layer, in place of sqlalchemy + psycopg2-binary + alembic. `prisma` is
# the whole of it: the client, the migration tool and the schema language, generated
# from `prisma/schema.prisma`. There is no separate driver — the query engine is a
# binary the package fetches and talks to over a local socket.
#
# Pinned exactly, because the version decides the *generated code*: `prisma generate`
# writes into the installed package, so an upgrade rewrites the client the application
# imports. Bump it deliberately and re-run the suite.
#
# It needs Node at **generate** time (the schema parser and migration engine are the
# upstream Prisma CLI), which is why the Dockerfile installs one. Nothing needs Node at
# runtime.
